# Fairmacs LMS — Notification System & Zoho Email Setup Guide

## 1. Current Operational Status

- **In-App Notification Centre**: **ENABLED & ACTIVE**
  - All LMS events (course assignments, deadline reminders, overdue escalations, module completions, quiz unlocks, assessment results/retakes, certificate issuance, manager team compliance alerts, and HR/Admin operational alerts) are persisted in PostgreSQL (`notifications` table) and delivered immediately in the Fairmacs LMS web interface.
- **Zoho Email Notification Channel**: **PREPARED & DISABLED BY DEFAULT**
  - Default configuration: `app.notifications.email.enabled=false` (`NOTIFICATION_EMAIL_ENABLED=false`).
  - The backend starts, runs, and processes all in-app notifications without requiring any Zoho SMTP or Zoho ZeptoMail credentials.
  - While disabled, `EmailNotificationChannel` performs zero external network or SMTP calls and never emits false email-failure alerts.

---

## 2. Architecture Overview

1. **`NotificationChannel` Interface** (`com.fairmacs.lms.service.notification.NotificationChannel`)
   - `InAppNotificationChannel`: Always active (`isEnabled() == true`).
   - `EmailNotificationChannel`: Controlled by `app.notifications.email.enabled` (`false` by default).
2. **`EmailTemplateRenderer`** (`com.fairmacs.lms.service.notification.EmailTemplateRenderer`)
   - Renders responsive corporate HTML and plain-text emails with safe links back to the Fairmacs LMS frontend (`FRONTEND_BASE_URL`).
   - Covers:
     - New Course Assignment (`COURSE_ASSIGNED`)
     - Course Deadline Reminder (`COURSE_DUE_SOON` — 7 days, 3 days, and due date)
     - Overdue Course Alert (`COURSE_OVERDUE` — initial + weekly repeat)
     - Course Completion & Certificate Issued (`COURSE_COMPLETED`, `CERTIFICATE_ISSUED`)
     - Assessment Passed / Failed / Retake Unlocked (`ASSESSMENT_RESULT`, `ASSESSMENT_FAILED`, `RETAKE_AVAILABLE`)
     - Manager Team Compliance Updates & Weekly Digest (`TEAM_COMPLIANCE`)
     - HR/Admin Operational Alerts & Weekly Digest (`HR_ADMIN_ALERT`, `SYSTEM_ALERT`)
     - Corporate Policy Assignment & Acknowledgement Reminder (`POLICY_ASSIGNED`, `POLICY_REMINDER`, `POLICY_ESCALATION`)
     - Organization Announcements (`GENERAL_ANNOUNCEMENT`)
3. **Delivery Tracking on `notifications` Table**
   - `email_status`: `DISABLED` (when email is off), `PENDING`, `SENT`, `FAILED`, `SKIPPED`
   - `email_attempts`: Number of delivery attempts
   - `email_last_attempt_at`: Timestamp of last attempt
   - `email_error`: Sanitized error summary (redacts any tokens/secrets)

## 3. Recommended Zoho Provider for Fairmacs (500+ Employees)

For automated transactional LMS notifications (course assignments, deadline reminders, assessment results, and weekly digests), **Zoho ZeptoMail** is strongly recommended over standard Zoho Mail personal/shared mailbox SMTP because:
- It is purpose-built for transactional application emails with high deliverability and burst capacity during department-wide course assignments.
- It uses HTTPS REST API (`https://api.zeptomail.in/v1.1/email` or `https://api.zeptomail.com/v1.1/email`), avoiding cloud hosting outbound SMTP port blocks on Render.
- It isolates transactional LMS traffic from regular corporate Zoho Mail user mailboxes.

## 4. Zoho Domain Verification Checklist (SPF, DKIM, Sender Address)

Before enabling email in production:
1. Log in to **Zoho ZeptoMail** (or Zoho Mail Admin Console).
2. Add and verify your sending domain (e.g., `fairmacs.com` or `lms.fairmacs.com`).
3. Configure DNS records at your domain registrar:
   - **SPF Record (`TXT`)**: Include `include:zeptomail.net` (or `include:zoho.in` / `include:zoho.com` per your Zoho region).
   - **DKIM Record (`TXT`)**: Add the selector and public key generated by Zoho ZeptoMail.
   - **DMARC Record (`TXT`, recommended)**: `v=DMARC1; p=none; rua=mailto:postmaster@fairmacs.com`
4. Create a verified sender address such as `no-reply@fairmacs.com` (`Fairmacs Learning Hub`) and obtain your **Send Mail Token** (`Zoho-enczapikey ...`).

## 5. Required Environment Variables

| Environment Variable | Default Value | Description |
| :--- | :--- | :--- |
| `NOTIFICATION_EMAIL_ENABLED` | `false` | Set to `true` **only** when ready to send live emails |
| `NOTIFICATION_EMAIL_PROVIDER` | `ZEPTOMAIL` | Email provider mode (`ZEPTOMAIL`) |
| `NOTIFICATION_EMAIL_FROM` | `no-reply@fairmacs.com` | Verified sender email address |
| `NOTIFICATION_EMAIL_FROM_NAME` | `Fairmacs Learning Hub` | Sender display name |
| `NOTIFICATION_EMAIL_REPLY_TO` | `fla@fairmacs.com` | Reply-to address for employee questions |
| `NOTIFICATION_EMAIL_MAX_RETRIES` | `3` | Maximum delivery attempts per notification |
| `ZEPTOMAIL_API_URL` | `https://api.zeptomail.in/v1.1/email` | Regional ZeptoMail endpoint (`.in`, `.com`, `.eu`) |
| `ZEPTOMAIL_SEND_TOKEN` | *(empty)* | Zoho ZeptoMail Send Mail Token (never commit to Git) |
| `FRONTEND_BASE_URL` | `http://localhost:5173` | Public Vercel URL in production (e.g. `https://lms.fairmacs.com`) |

## 6. How to Enable Email Locally (For Testing)

1. Set environment variables in your terminal (or local `.env` / IDE run configuration — never commit secrets to Git):
   ```powershell
   $env:NOTIFICATION_EMAIL_ENABLED="true"
   $env:ZEPTOMAIL_API_URL="https://api.zeptomail.in/v1.1/email"
   $env:ZEPTOMAIL_SEND_TOKEN="Zoho-enczapikey <your-token>"
   $env:NOTIFICATION_EMAIL_FROM="no-reply@fairmacs.com"
   $env:FRONTEND_BASE_URL="http://localhost:5173"
   ```
2. Start the backend:
   ```powershell
   mvn -f backend/pom.xml spring-boot:run
   ```
3. Log in as **HR Admin**, open **HR Overview -> Announcements**, and verify that **Zoho Email Channel** shows `ENABLED`.
4. Send a test announcement to a single test user or department and verify that `notifications.email_status` transitions to `SENT`.

## 7. How to Enable Email on Render (Production)

1. Open your **Render Dashboard** -> select the **Fairmacs LMS Backend** web service -> **Environment**.
2. Add the environment variables:
   - `FRONTEND_BASE_URL` = `https://<your-vercel-domain>`
   - `ZEPTOMAIL_API_URL` = `https://api.zeptomail.in/v1.1/email`
   - `ZEPTOMAIL_SEND_TOKEN` = `Zoho-enczapikey <your-production-token>`
   - `NOTIFICATION_EMAIL_FROM` = `no-reply@fairmacs.com`
   - `NOTIFICATION_EMAIL_FROM_NAME` = `Fairmacs Learning Hub`
   - `NOTIFICATION_EMAIL_REPLY_TO` = `fla@fairmacs.com`
   - `NOTIFICATION_EMAIL_ENABLED` = `true`
3. Save changes to trigger a redeploy.

---

## 8. How to Disable Email Quickly (Emergency Rollback)

If you ever need to pause all outbound emails immediately without affecting in-app notifications:
1. Set `NOTIFICATION_EMAIL_ENABLED=false` (or `app.notifications.email.enabled=false`) in Render Environment Variables.
2. Restart/redeploy the service. In-app notifications will continue operating normally with zero interruption.
